# **Blooky Vision**

> **a small rebellion for the joy of building**

— この文書は、blooky がなぜ生まれたのか、何を目指しているのかを語るマニフェストです。
技術仕様ではなく、思想と設計哲学を伝えるためのものです。

---

## 1. Why we build — なぜつくるのか

プログラミングは本来、**つくる喜び**に満ちた営みです。
しかし現代の Web 開発は、複雑なツール群や依存関係に囲まれ、
「作る楽しさ」よりも「壊さないための管理」に多くの時間を費やすようになりました。

blooky は、この現状に対して――
とても小さな、けれど明確な意思をもって企てた **反逆** です。

「もっと気軽に作りたい」「コードを組み合わせる感覚を取り戻したい」。
その願いのもとに、blooky は生まれました。

破壊的代入や複雑なライフサイクルに縛られるのではなく、
**点と点をつないで流れを作る**──そんな自然な感覚を、
アプリケーションを生み出すプロセスに取り戻したいのです。

---

## 2. The Problem — 分断された開発体験

Web 開発は成熟したように見えて、その内側では分断が進んでいます。
UI、状態管理、副作用、非同期処理、データフロー……。
それぞれが独自の文法とライフサイクルを持ち、
開発者はそれらを**翻訳しながら**プロジェクトを進めなければなりません。

この分断は、生産性だけでなく **思考の流れ** を断ち切ります。
「データがどこから来て、どこへ行くのか？」を追うたびに、
異なる文脈に飛び込まなければならないのです。

---

## 3. The Core — Stream / Prop / fx

blooky は、この分断を解くために、
**Stream（流れ）・Prop（状態）・fx（副作用）** の三つを核にした
**統一的な抽象**を提案します。

* **Stream** は出来事の流れ
* **Prop** はその時点の状態
* **fx** は外界との対話（副作用）

これらは分離したレイヤーではなく、**一つの連続したデータフロー**の中にあります。
UI・非同期処理・状態更新の境界をなくし、
「流れとしてアプリケーションを考える」ための言語です。

---

## 4. The Principles — 設計の原則

> **Declarativity / Transparency / Structural Consistency / Respect for Web Standards**

### 1. 宣言性 — *Declare, not instruct.*

「何をどうするか」ではなく、**「どんな関係が成り立つか」**を記述する。
読むことと動くことが一致する、そんなコードを目指します。

### 2. 透明性 — *Nothing hides behind magic.*

blooky は“魔法”を避けます。それは単に「仕組みを隠さない」ことに留まりません。
「なぜ動かないのか？」という問いに、DevTools が視覚的な答えを提示します。
透明性とは、「コードに触れ続けたい」という**意志を支える土台**なのです。

### 3. 構造的一貫性 — *One structure, many scales.*

小さな部品も大きなアプリも、
**Stream → Prop → fx** の構造で語れる。
blooky のアプリケーションは、**自己相似的に成長する有機体**です。

### 4. Web標準への敬意 — *Built on the solid ground.*

blookyは新しい魔法ではなく、Web標準の力を最大化します。
学びは流行ではなくMDNと仕様書に還元でき、
Web の進化と共に歩む一歩一歩が、着実な力となります。

---

## 5. The Craft — 作るという体験

blooky が変えようとしているのは、「書き方」ではなく
**開発という行為そのものの体験**です。

* 概念を理解する体験：すべてが「流れ」という原理に収束する
* 問題を分解する体験：Stream / Prop / fx の責務が明確
* デバッグする体験：可視化によって「観察」が可能に
* コードを育てる体験：リファクタリングが「成長」に変わる

> プログラミングを再び、**触れるものづくり**に戻す。

---

## 6. The Joy of Building — 作ることの喜び

blooky の世界では、すべてが “流れ” です。
クリックも、データも、アニメーションも──
それぞれが小さな流れとなり、合流し、分岐し、形を変えていきます。

これは理論ではなく、**遊びのための規則性**です。
Scratch が、あるいはレゴが、Minecraftが、ブロックで世界を作るように、
blooky は **関数とデータフロー** で世界を組み立てます。

> 見える。
> 触れる。
> だから、試せる。

それが blooky の目指す開発体験です。

---

## 7. Epilogue — 創造の自由のために

blooky は、純粋な意味での「関数型フレームワーク」を標榜するものではなく、
**関数型の精神を借りた、創造のための遊び場**です。

データが流れ、構造が見え、試行錯誤できる世界。
その中で、思いつくどんな小さなアイデアも、
すぐに形にできるように──

blooky は、コードを書くことがもう一度楽しくなる世界を目指しています。
ひとりひとりが、**作ることを楽しめるようにするために。**
この小さな、小さな反逆の芽を、ゆっくりと育てていこうと思います。
